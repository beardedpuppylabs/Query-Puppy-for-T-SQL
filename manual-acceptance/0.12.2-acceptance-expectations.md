# 0.12.2 focused manual acceptance

**Manual acceptance: PENDING RE-ACCEPTANCE**

This suite validates the trigger and DML stabilization repair in the real
VSCodium, Microsoft mssql, and IntelliSenseLab environment.

## Required setup

The active mssql editor database must be **IntelliSenseLab**, and the existing
`qpacc` fixture must already be provisioned. The provisioning script
`manual-acceptance/extend-intellisenselab-0.11.0-fixtures.sql` ends in
`IntelliSenseLabReporting`; explicitly switch the editor connection back to
`IntelliSenseLab` before testing. After provisioning or changing databases, run
**Query Puppy for T-SQL: Refresh Schema Metadata** when cached metadata may be
stale. Do not run fixture DDL as part of this suite.

Every intentionally incomplete test is **RUN ALONE IN A FRESH SQL EDITOR**.
Generic editor `abc` suggestions are ignored and do not count as Query Puppy
semantic results. Expected candidates remain outside the SQL file so word-based
suggestions cannot create false positives.

The suite passes only when automatic and manual Query Puppy domains agree where an
automatic trigger is intentionally supported, triggers operate on the post-edit

blank DML targets do not force the multi-provider popup, and DML expression phases
remain separate.
